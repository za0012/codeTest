# 모아 MOA

코딩 테스트 풀이를 **스터디 단위로 모아 검색**하고, 활동을 **통계와 히트맵**으로 확인하는 웹 서비스입니다.

> 개인 프로젝트 · 개발 중 (외부 배포 전)

---

## 만든 이유

직접 참여한 코딩 테스트 스터디에서 풀이가 채팅방·GitHub·블로그에 흩어져 있었습니다.

- 이전에 공유된 풀이를 다시 찾기 어려웠습니다
- 스터디원별 풀이량과 꾸준함을 한눈에 파악하기 어려웠습니다

풀이를 스터디 단위로 모아 검색하고, 웹에서 반복되던 등록 과정은 Chrome 확장으로 줄이는 것을 목표로 만들고 있습니다.

---

## 주요 기능

### 스터디 참여와 권한
참여 코드로 스터디에 참여합니다. Supabase RLS로 **스터디장에게만 수정·삭제 권한**을 부여하고, 삭제는 7일 내 취소할 수 있습니다.

### 풀이 검색
문제명·플랫폼·난이도·풀이자를 조합해 검색합니다. 검색 조건을 **queryKey에 반영**해 조건이 바뀔 때만 목록을 다시 조회합니다.

### 활동 통계
월별 추이와 난이도 분포를 보여줍니다. 기록이 없는 달은 0으로 보간하고, **플랫폼마다 다른 난이도를 공통 단계로 변환**해 하나의 차트에서 비교합니다.

### SVG 활동 히트맵
사용한 Recharts 버전에 달력형 히트맵이 없어, 최근 12개월 날짜의 **주·요일 좌표와 풀이량별 4단계 색상을 직접 계산**해 SVG로 구현했습니다.
정적 `<circle>`에 마우스 이벤트를 직접 넣으면 접근성 규칙에 걸려, 각 날짜 원 위에 **투명 `<button>`을 겹쳐** `aria-label`과 포커스 스타일을 부여했습니다. 마우스 없이도 날짜별 풀이량을 확인할 수 있습니다.

### Chrome 확장 (프로그래머스 → MOA)
프로그래머스 통과를 감지해 문제 정보와 에디터 코드를 불러옵니다. **난이도·메모는 사용자가 확인한 뒤 저장**하며, 자동 저장은 적용하지 않았습니다.
페이지 컨텍스트에서 읽은 코드는 `CustomEvent → content script → service worker → Next.js API` 순으로 전달합니다.

## 기술 스택

| 구분 | 사용 |
|---|---|
| 프레임워크 | Next.js 16 (App Router) · TypeScript 5 |
| 스타일 | Tailwind CSS 4 |
| 데이터 | Supabase (Postgres · Auth · RLS) |
| 상태·폼 | TanStack Query 5 · Jotai · React Hook Form |
| 시각화 | Recharts 3 · SVG (히트맵 직접 구현) |
| 그 외 | Chrome Extension (Manifest V3) · Notion API |

---

## 구조

데이터 조회(`service`) · 상태(`hook`) · 화면(`view`)을 분리해, 기능을 추가해도 화면과 로직이 뒤섞이지 않도록 구성했습니다.

Figma Make로 만든 초기 코드는 600줄 이상의 페이지 컴포넌트에 폼·상태·모달 로직이 뒤섞여 있었습니다. 컴포넌트 분리와 React Hook Form·TanStack Query 적용을 시도했지만 기존 구조를 유지하며 고치는 방식으로는 복잡도를 줄이기 어렵다고 판단해, 기존 코드는 별도 브랜치에 보관하고 App Router 프로젝트에서 다시 시작했습니다.

## 실행

```bash
bun install
bun dev
```

`.env.local`에 Supabase 프로젝트 URL과 anon key가 필요합니다.

```
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
```

Chrome 확장은 `chrome://extensions` → 개발자 모드 → **압축해제된 확장 프로그램을 로드**로 불러옵니다.

## 개발 과정에서 다룬 문제

### 타임존 말일 누락
날짜 키를 `toISOString()`으로 만들며 KST가 UTC로 하루 밀려, 말일에 등록한 풀이가 히트맵에 나타나지 않았습니다. 날짜 개수(365개)는 정상이라 눈으로는 드러나지 않았습니다.
로컬 포맷으로 교체한 뒤 **말일 포함 여부를 경계값 테스트로 고정**했습니다.

### 툴팁 중복 렌더링
hover 시 툴팁 테두리가 흐릿하게 번지고 비정상적으로 두껍게 보였습니다. 툴팁을 날짜 반복문 안에서 렌더링해 **hover 한 번에 같은 자리에 365개가 겹친** 것이 원인이었습니다.
툴팁을 반복문 밖으로 빼 한 번만 렌더링하고, hover된 날짜의 좌표만 상태로 관리하도록 바꿔 해결했습니다.

### 리뷰 공백을 메우는 검증 자동화
혼자 개발하는 프로젝트라 리뷰를 받을 사람이 없어, PR마다 GitHub Actions에서 lint·타입 검사·테스트·빌드를 실행하고 변경 diff를 리뷰해 **P1 결함이 있으면 병합을 차단**하도록 구성했습니다.
예약 작업이 커밋·작업 트리·의존성 변경을 SRP·타입 안정성·접근성·네이밍 기준으로 점검한 리포트를 Notion에 자동 기록합니다.

## 현재 범위

- 외부 배포 전이며, 개발 환경에서 직접 사용·검증하고 있습니다
- Chrome 확장은 개발자 모드로 사용 중입니다
- 스터디 **생성은 미구현**이며, 참여 코드를 통한 기존 스터디 참여까지 동작합니다
- 차트 가공 로직에는 타임존 고정 테스트를 두고, 그 외에는 빌드·정적 검사·화면 확인으로 검증하고 있습니다
